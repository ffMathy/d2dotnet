# d2go for .NET

A C# port of [d2go](https://github.com/hectorgimenez/d2go) (MIT, (c) 2023 Héctor Giménez), the Go library that reads
the state of a running Diablo II: Resurrected game, as forked at [Farmith/d2go](https://github.com/Farmith/d2go),
commit `1072577f86e79cb68cd74295666041f6010e07a7`.

| Folder | Namespace | Go source |
| --- | --- | --- |
| `src/D2Dotnet.D2Go.Data` | `D2Dotnet.D2Go.Data` (+ `.Area`, `.Difficulty`, `.Item`, `.Npc`, `.Object`, `.Quest`, `.Skill`, `.Stat`, `.State`) | `pkg/data` and its subpackages: the game state model |
| `tests/D2Dotnet.D2Go.Data.Tests` | | unit tests, plus oracle tests against the Go source |

Only `pkg/data`, `pkg/memory` and `pkg/utils` are in scope; `pkg/nip` and `cmd/` are not ported.

## No game data in this repository

d2go compiles six tables into its Go source, generated by `cmd/txttocode` from the game's excel files (items,
item types, levels, skills, skill descriptions, objects). This port does **not** contain them. `GameTables` builds the
same tables at run time from the game files, through `IGameFileProvider` of
[`D2Dotnet.Map.GameData`](../map/src/D2Dotnet.Map.GameData/README.md) (a D2R install or a folder of extracted files):

```csharp
using D2Dotnet.D2Go.Data;
using D2Dotnet.Map.GameData;

IGameFileProvider provider = GameFileProviders.Open(@"C:\Program Files (x86)\Diablo II Resurrected");
GameTables tables = GameTables.Load(provider);          // reads data/global/excel/*.txt

Console.WriteLine(tables.ItemDesc(589).Name);            // Go: item.Desc[589].Name
GameItem potion = new() { Id = 589 };
Console.WriteLine(potion.IsHealingPotion(tables));       // Go: potion.IsHealingPotion()
```

What *is* committed are identifiers (the id enums `AreaId`, `NpcId`, `ObjectName`, `SkillId`, `StatId`, `StateId`,
`QuestId`, the item type codes and item names) and d2go's hand-written logic and lists (waypoints, terror zones,
belt, key bindings, monster and object classification, quest status), as for `LevelIds` in the map tool.

### Generated tables

Every table is built exactly as `cmd/txttocode` builds the Go source: same file, same columns, rows whose **second
column** is empty are skipped (the generator's "Ignore if Code is empty" rule, whatever that column is called), and
the same keys and ids. The dictionaries are the Go maps; the lookup methods are Go's map index, which gives the zero
value for a missing key.

| Go | Source columns (`data/global/excel/`) | C# dictionary | C# lookup |
| --- | --- | --- | --- |
| `item.ItemTypes map[string]Type` | itemtypes.txt: key `Code`; `ID` = row index, `Name` = `ItemType`, `Code`, `Throwable` and `Beltable` = cell is `1` | `GameTables.ItemTypes` | `tables.ItemType(code)` |
| `item.Desc map[int]Description` | weapons.txt, armor.txt, misc.txt in that order, one running id: `name` (with the generator's spelling fixes), `code`, `normcode`, `ubercode`, `ultracode` (all three empty when the file has no `normcode`), `invwidth`, `invheight`, `minac`/`maxac` (0 when absent), `type` | `GameTables.ItemDescriptions` | `tables.ItemDesc(id)` |
| `area.Areas map[ID]Area` | levels.txt: key and `ID` = row index, `Name` = `LevelName` | `GameTables.Areas` | `tables.Area(id)` |
| `skill.Skills map[ID]Skill` | skills.txt: key `*Id`; `ID` = row index, `Name` = `skill`, `leftskill`, `rightskill` | `GameTables.Skills` | `tables.Skill(id)` |
| `skill.Desc map[ID]Description` | skilldesc.txt: key = row index; `SkillPage`, `SkillRow`, `SkillColumn`, `ListRow`, `IconCel` | `GameTables.SkillDescriptions` | `tables.SkillDesc(id)` |
| `object.Desc map[int]Description` | objects.txt: key and `ID` = `*ID`; `Name`, `SizeX`, `SizeY`, `HasCollision` = `HasCollision0` is `1` | `GameTables.ObjectDescriptions` | `tables.ObjectDesc(id)` |

### Names

C# names are PascalCase with `Id` for `ID` and `Npc` for `NPC` (`HP`, `MP`, `WP`, `KB` stay upper case). Types
are renamed where the Go name would clash with a namespace (`D2Dotnet.D2Go.Data.Item` and a type `Item` cannot share
a namespace) or be ambiguous from other `D2Dotnet.D2Go.*` code:

| Go | C# | Go | C# |
| --- | --- | --- | --- |
| `data.Data` | `GameData` | `quest.Quest`, `Status`, `States` | `QuestId`, `QuestStatus`, `QuestStates` |
| `data.Item` | `GameItem` | `skill.ID`, `Skill`, `Description`, `Points` | `SkillId`, `SkillInfo`, `SkillDescription`, `SkillPoints` |
| `data.Object`, `Objects` | `GameObject`, `GameObjects` | `stat.ID`, `Data` | `StatId`, `StatData` |
| `data.NPC`, `NPCs` | `GameNpc`, `GameNpcs` | `state.State` | `StateId` |
| `data.UnitID` | `UnitId` | `item.Description`, `Type`, `Location`, `Quality`, `Tier`, `Name` | `ItemDescription`, `ItemType`, `ItemLocation`, `ItemQuality`, `ItemTier`, `ItemName` |
| `[2]byte` (key) | `KeyBytes` | `object.Name`, `Description` | `ObjectName`, `ObjectDescription` |
| `area.ID`, `Area`, `WPAddress` | `AreaId`, `AreaInfo`, `WPAddress` | `difficulty.Difficulty` | `GameDifficulty` |
| `npc.ID` | `NpcId` | | |

Constants: Go `iota` constants are C# enums with the same underlying size and numeric values (`AreaId`, `NpcId`,
`ObjectName` are `int`; `SkillId`, `StatId`, `QuestId`, `QuestStatus` are `short`; `StateId`, `Class`,
`InteractType`, `ShrineType` are `uint`). A redundant type prefix is dropped: `MonsterTypeUnique` is
`MonsterType.Unique`, `LocationStash` is `LocationType.Stash`, `QualityMagic` is `ItemQuality.Magic`, `TierElite`
is `ItemTier.Elite`, `StatusRewardGranted` is `QuestStatus.RewardGranted`, `InteractTypeLocked` is
`InteractType.Locked`. Untyped string constants stay `const string`: `item.TypeHealingPotion` is
`ItemTypeCodes.TypeHealingPotion`, `item.ScrollOfTownPortal` is `ItemNames.ScrollOfTownPortal`, `difficulty.Hell` is
`GameDifficulty.Hell`. Package variables live on a static class: `item.Names` is `ItemNames.Names`,
`stat.StringStats` is `StatNames.StringStats`, `skill.SkillNames` is `SkillNames.Names`, `object.ShrineTypeNames` is
`ShrineTypes.ShrineTypeNames`, `area.WPAddresses` is `Waypoints.WPAddresses`, `area.CanBeTerrorized` is
`TerrorZones.CanBeTerrorized`, and `data.MonsterEliteFilter()`/`MonsterAnyFilter()` are on `MonsterFilters`.

Functions returning `(T, bool)` follow the `Try` pattern; on a miss the `out` value is Go's zero value:

| Go | C# |
| --- | --- |
| `Stats.FindStat`, `PlayerUnit.FindStat`, `Item.FindStat` | `TryFindStat` |
| `Inventory.Find(name, locations...)` | `Inventory.TryFind(name, out item, locations)` |
| `NPCs.FindOne`, `Monsters.FindOne`, `Objects.FindOne` | `TryFindOne` |
| `Monsters.FindByID`, `Objects.FindByID` | `TryFindById` |
| `Roster.FindByName` | `Roster.TryFindByName` |
| `Belt.GetFirstPotion` | `Belt.TryGetFirstPotion` |
| `KeyBindings.KeyBindingForSkill` | `KeyBindings.TryGetKeyBindingForSkill` |

Go `String()`/`ToString()` methods on numeric types become `StatId.ToStatString()` and
`ItemQuality.ToQualityString()` (a C# enum's own `ToString()` cannot be replaced).

## Differences from Go

Behaviour is Go's, including its edge cases and bugs. Where the representation differs:

* **Value types.** Go structs with only numbers are `readonly record struct`s; those with strings or collections are
  `sealed record`s with init-only properties whose defaults are Go's zero value (`""`, empty collections). Go named
  string types (`MonsterType`, `PotionType`, `LocationType`, `ItemName`, `Resist`, `GameDifficulty`) are structs that
  convert implicitly from `string`, compare ordinally, and whose default is `""`, so `default(MonsterType)` is Go's
  zero value `""`, not `MonsterType.None` (`"None"`).
* **Collections.** Named slices (`Monsters`, `GameNpcs`, `GameObjects`, `Roster`, `Stats`, `States`, `QuestStates`)
  are read-only collections that support collection expressions; other slices are `IReadOnlyList<T>`, Go maps are
  `IReadOnlyDictionary`. A nil slice or map is an empty collection. Go arrays keep their length as defaults:
  `Inventory.StashedGold` (4), `KeyBindings.Skills` (16), `KeyBindings.UseBelt` (4); `[2]byte` is `KeyBytes`.
  `CollisionGrid` is `bool[][]`. `Widgets` is `IReadOnlyDictionary<string, IReadOnlyDictionary<string, object?>>`.
  `area.CanBeTerrorized` (`map[ID]bool`, every value `true`) is an `IReadOnlySet<AreaId>`. `Quests` adds
  `StatesOf(quest)` for Go's `quests[q]`, which gives empty states for a missing quest.
* **Embedding.** Promoted members are written out: `Room.X`/`Y`, `SkillBinding.Key1`/`Key2`, `AreaInfo.IsTown()`,
  `CanBeTerrorized()`, `Act()`, `Area()`, `SkillInfo.Desc()`, `GameObject.Desc()`; the embedded value itself is a
  property (`Room.Position`, `GameItem.UnitId`, `GameObject.Name`, `ItemLocation.LocationType`, ...).
* **Integers.** Go's `int` is 64-bit; the port uses `int` (and `uint` for Go `uint`, `nuint` for `uintptr`).
  Float-to-int conversions follow Go on amd64 (truncation; the minimum integer for NaN, infinities and out of range
  values), so `HPPercent()`/`MPPercent()` with a max of 0 and `MercHPPercent()` with a max life of 0 give
  `int.MinValue` where Go gives `math.MinInt64`. `CastingFrames()` keeps Go's 64-bit intermediate products.
* **Panics.** Where Go panics, the port throws: `ItemNames.GetNameByEnum` and `StatId.ToStatString` with an id
  outside their list (`ArgumentOutOfRangeException`), `KeyBytes[i]` and `Room.GetWalkableTiles` outside the grid
  (`IndexOutOfRangeException`).
* **Case folding.** `strings.EqualFold` (`Inventory.TryFind`, `Roster.TryFindByName`, `ItemNames.GetIdByName`) is
  emulated rune by rune with invariant upper and lower case mapping, which covers Go's simple folding for the names
  these compare (including folds like the Kelvin sign and `k`).
* **Unexported names.** Go's lower-case constants that the exported API uses are public members:
  `SkillId.MonInfernoSentry`, `MonDeathSentry`, `SentryLightning`, `FenrisRage`, `DeathSentryLtng` (keys of
  `skill.SkillNames`, whose values keep the Go spelling) and `ObjectName.Dummy411`, `Dummy412`. `goldPerLevel` is a
  private constant.
* **`object.NotSoGoodChestName`.** In Go this is an untyped `int` constant (581), evidently a typo for
  `NotSoGoodChest Name = 581`. It is the `ObjectName.NotSoGoodChestName` member here, with the Go name.

### Go behaviour kept on purpose

* `skill.ID.Desc()` indexes `skill.Desc`, which is keyed by skilldesc.txt **row index**, with a skill id. Rows are not
  in skill id order, so for most skills this is another skill's row or the zero value. `SkillInfo.Desc()` uses the
  skill's `ID`, which the generator sets to the skills.txt row index, not to `*Id`.
* `ItemQuality.Crafted.ToQualityString()` is `"UnknownItemQuality"`: Go's switch has no `QualityCrafted` case.
* `Room.GetWalkableTiles(d, room)` ignores its receiver and scans `room`.
* `ItemDescription.Tier()` of the zero value is `Elite` (all codes are empty, so `Code == UltraCode`).
* `Monsters.TryFindOne(id, type)` matches any type only for `MonsterType.None`; the zero `MonsterType` (`""`) matches
  only monsters whose type is `""`.
* `KeyBindings.TryGetKeyBindingForSkill(SkillId.AttackSkill)` finds the first unset skill slot (unset slots hold
  skill 0), returning a zero binding and `true`.
* `Inventory.ByLocation` lists an item once per matching location argument, so repeated locations repeat items.
* `Belt.TryGetFirstPotion` matches the potion type with a case-sensitive substring of the item name.
* `OpenMenus.IsMenuOpen()` ignores `LoadingScreen` and `MapShown`.

### Reading the excel tables

`GameTables` reads files as the generator does (`bufio.ScanLines`: `\n` or `\r\n` line ends, no empty last line;
`strings.Split(line, "\t")`; cells kept verbatim, so the `"Broad Axe "` name keeps its trailing space). It is lenient
where the generator would crash or write code that does not compile:

* column names are matched exactly first, then ignoring case (the generator is case-sensitive); with duplicate
  names the last column wins, as in the generator's map;
* a UTF-8 byte order mark is skipped;
* missing cells of a short row, and blank lines, read as empty (the generator panics), so such rows are skipped;
* a number cell may have surrounding blanks, and an empty one is 0; numbers are decimal (Go would read a leading `0`
  as octal in the generated literal);
* a duplicate key keeps the last row (a compile error in Go); a skills.txt `*Id` or row index outside the 16-bit
  range of `SkillId` is an `OverflowException` (also a compile error in Go);
* a missing table is a `FileNotFoundException`, a missing column a `InvalidDataException` (the generator writes
  `<no value>`), except the columns the generator itself defaults: `name` (empty), `minac`/`maxac` (0) and
  `normcode`/`ubercode`/`ultracode` (all empty when `normcode` is absent).

## Tests

```bash
dotnet test tools/d2go/tests/D2Dotnet.D2Go.Data.Tests
```

The tests use d2go itself as an oracle. `tests/D2GoFixtures.targets` downloads the pinned commit
(`codeload.github.com/Farmith/d2go/tar.gz/<sha>`) into the gitignored `<repo>/.cache/d2go/` on the first build; a
failed download does not break the build, but the oracle tests then fail with a message saying so (they never skip).
To work offline, put the codeload tarball `d2go-<sha>.tar.gz`, or its extracted `d2go-<sha>/` folder with an empty
`.extracted` file, in `.cache/d2go/`.

* `GeneratedTablesOracleTests` loads `GameTables` from d2go's `cmd/txttocode/txt/*.txt` and compares every entry of
  every table with the Go literals of the six generated files.
* `ConstantsOracleTests` evaluates every constant declaration of `pkg/data` (with `iota`) and compares it with the C#
  enums and constants, both ways; compares the hand-written lists (`Names`, `StringStats`, `SkillNames`,
  `ShrineTypeNames`, `WPAddresses`, `CanBeTerrorized`); and checks every id switch (`IsMerc`, `IsPet`, `IsGoodNPC`,
  `IsMonsterRaiser`, `IsSkip`, `IsShrine`, `IsWaypoint`, `IsPortal`, `IsRedPortal`, `IsChest`, `IsDoor`,
  `IsSuperChest`, `IsTown`, `HasDebuff`) for ids -2 to 1097.
* The other tests cover every method with a branch. Expected numbers of `CastingFrames`, `HPPercent`, `MPPercent`,
  `MercHPPercent` and `Act` were produced by running d2go's Go code. Loader rules are tested with small synthetic
  tables (no game data).
